## REQUEST_CHANGES

### MAJOR

**M1 — Workspace scan re-registers prior turns' artifacts as new Creations; no duplicate prevention.**
`crates/project-agent/src/service.rs:100` (`merge_artifacts`) + `:337` (`collect_workspace_files`) merge a full recursive scan of the *persistent* `projects/<pid>/workspace/` into every run's artifact list, and `run` registers every non-sidecar artifact with no check against already-registered Creations (`project-core::create_creation` always mints a new id, `crates/project-core/src/lib.rs:874`). Because `merge_artifacts` dedupes only by path *within one run*, any file left in the workspace by an earlier turn is registered again on every subsequent turn, and `crates/project-app/src/app.rs:928-938` attaches **all** of `result.registered` to *that turn's* assistant message.

Concrete acceptance-visible failure on the exact M10 flow: turn 1 writes `workspace/index.html` → card "index". Turn 2 ("cambiá el color") writes `workspace/actividad-2/index.html`; sorted paths register `actividad-2/index.html` **and** the turn-1 `index.html` again → the turn-2 bubble shows two cards (one being the old activity), and `prepare_share_visibility`'s no-id fallback (`crates/project-app/src/app.rs:1296-1303`, `.rev().find(Web)`) now promotes the **stale** turn-1 duplicate, since it is registered last. The same amplification occurs after any backend restart (`ensure_ready` clears cached sessions, `opencode.rs:186-193`), where the diff no longer contains older files but the scan does.

Required fix (bounded): keep the scan as the B1 fallback rather than an unconditional superset — either (a) at `service.rs:100`, only fall back to `scan_workspace_artifacts` when the diff produced no registrable artifact, or (b) restrict the scan to files created/modified during this run (capture a start `SystemTime` before `engine.send` and filter on `meta.modified()`). Option (a) preserves `workspace_scan_registers_when_diff_is_empty` (`tests/agent_service.rs:340`) unchanged; option (b) requires that test to write the file after run start.

### MINOR

**m1 — Internal file name leaks into user-facing label.** `crates/project-agent/src/registrar.rs:131-150` + `:78-86`: the new instruction tells the model to put `index.html` at the workspace root (`service.rs:203`), which is exactly the case where `web_display_name` returns `None` (parent is empty) and the display name falls back to the stem `"index"`. A teacher sees a Creation named "index" in the card and Creations panel, contrary to the source-of-truth "no internal technical detail in default UX" rule. Fix: when the stem is `index`/`htm(l)`, use a human label (e.g. the project name threaded into `register`, or a generic "Actividad") instead of the file stem.

**m2 — Sidecar copy can produce a Creation that Compartir then refuses to publish.** `registrar.rs:187-250` copies siblings verbatim into `outputs/<id>/`, but the snapshot validator rejects root-level `files/` and `materials.html` (`RESERVED_ROOTS`, `crates/project-fs/src/publication_snapshot.rs:25,458`) and Windows-reserved stems (`aux.js`, `con.html`, `:465-479`). Those names are common enough in generated bundles that registration succeeds and publish fails later with a generic error. Fix: skip root-level reserved names and apply the same `validate_component` rules when copying.

**m3 — Nested `index.html` silently dropped.** `registrar.rs:244-246` skips *every* file named `index.html` at any depth, so a multi-page artifact (`slides/index.html`) loses its subpages and relative links 404 in Abrir/Compartir. The root case is already handled by the primary-name check at `registrar.rs:236`; the guard should apply only to `dest_root` itself.

**m4 — Unbounded scan/copy of the workspace.** `service.rs:337-385` and `registrar.rs:187` have no depth/file-count/size cap and no exclusion of dependency or build trees (`node_modules`, `dist`, `.venv`) — only `materials` and dot-entries. The OpenCode sidecar is a general coding agent; one `npm`-style detour turns every dependency file into a Creation (each read fully into memory by `read_workspace_artifact`/`register`) or into the published bundle. Fix: skip dependency/build dir names alongside `materials` and add a file-count/byte ceiling.

**m5 — Poll loop now hits the sidecar's `/diff` every 20 ms, and an empty reply without files spins to the 120 s timeout.** `crates/project-agent/src/opencode.rs:103-121`: `fetch_artifacts` is called on each `STATUS_POLL_INTERVAL` tick while the assistant shell has no text, and the 2 s grace applies only when `!artifacts.is_empty()`; empty-text + no-files now runs the full `DEFAULT_TASK` (120 s) as ~18k requests and then reports a failure (previously it returned immediately). Fix: start the same idle grace regardless of artifacts, and fetch the diff once when the grace begins rather than per tick.

**m6 — A11y: creation-card actions have no per-Creation accessible name.** `app/src/components/CreationsPanel.tsx:88-99` — every card exposes identically named "Abrir" and "Compartir" buttons with no relation to the creation, so with multiple cards in one bubble (which M1 makes routine) AT users cannot tell which artifact a button targets. Fix on the touched control: `aria-label={`${messages.sharing.shareAction}: ${creation.displayName}`}` (same for Abrir). Otherwise the touched UI is sound: Settings dialog keeps `role="dialog"`/`aria-modal`/labelledby, focus trap restores focus and handles Tab/Escape (`ui/useFocusTrap.ts`), the composer label is `sr-only`-paired, `modelOptionLabel` extraction keeps option text non-raw, and the composer's `justify-content` change doesn't drop focus styles.

**m7 — No coverage for the new filesystem sidecar path.** The B1 sibling-copy claim (`registrar.rs:158-250`) and the Web `index.html` storage rename are exercised only indirectly by the two new `app_facade` tests for the primary file; no test asserts a sibling lands in `outputs/<id>/` or in `publish/`. `tests/agent_service.rs:363` uses `FakeRegistrar`, which bypasses the copy entirely.
