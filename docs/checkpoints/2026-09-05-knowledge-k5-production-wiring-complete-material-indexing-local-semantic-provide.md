## KNOWLEDGE K5 PRODUCTION WIRING COMPLETE — material indexing + local semantic provider + acceptance closure (2026-09-05)

- **Production Material → Knowledge wiring — COMPLETE:** every production Material entry point now ends in `AppState::add_material_and_index`, which stores the Material first (authoritative acceptance) and only then derives Knowledge independently. Knowledge derivation never rolls back or rejects an accepted Material, and `remove_material` pairs ordinary Material removal with `remove_knowledge_material`. Covered entry points: `add_material_from_path`, `add_material_image` (clipboard paste), and `import_materials` (multi-file batch) — all routed through `add_material_and_index`; the Tauri command layer is unchanged.
- **Local semantic provider — COMPLETE (K2 design):** `AppState` owns one process-local `knowledge_provider: Mutex<Option<OrtEmbeddingProvider>>`. `with_local_embedding_provider` lazily loads it only when BOTH the verified first-use model AND the bundled ONNX Runtime library exist (`load_local_embedding_provider` uses `ModelManager::inspect` == `Verified`, `runtime_library_from_executable`, the tokenizer, and `OrtEmbeddingProvider::load`). Missing/corrupt model or runtime is an expected lexical-only state; the code never installs or contacts any remote embedding provider. AgentEngine stays provider-independent (no ONNX Runtime coupling to remote LLM providers).
- **Retrieval path:** `prepare_knowledge_context` runs K3 `hybrid_search` with the local provider when available, then K4 `assemble_context`, then K5 deterministic `serialize_knowledge_context` into the single remote request. When the provider is absent or semantic execution fails safely, K3 falls back to lexical retrieval — the whole chat request never fails solely because semantics are unavailable.
- **Acceptance matrix closure (`crates/project-app/tests/knowledge.rs`):** 13 focused tests cover TXT/Markdown accepted + lexically indexed → `Ready`; unsupported format accepted with durable `Unsupported`; indexing failure leaves the Material accepted with retryable `Failed`; lexical readiness when the model/runtime is absent; deletion cleaning source+status; same-content canonical reuse with scoped delete; project isolation; production turn injecting bounded untrusted `<knowledge_evidence>` without absolute paths/DB internals/duplicate raw attachment forwarding; deterministic K5 serialization across identical turns; normal non-indexed attachment behavior; and lexical fallback never contacting a remote provider. No remote embedding calls; no full-corpus transfer; document/chunk contents are never logged.
- **Calls/privacy:** MATERIAL INDEXING / EMBEDDING / RETRIEVAL / CONTEXT ASSEMBLY REMOTE LLM CALLS: ZERO. The remote LLM receives only the bounded K4-selected evidence, never the corpus, DB, vectors, model files, or absolute local paths.
