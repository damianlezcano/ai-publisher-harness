## FEDORA ACCEPTED-SEND LIFECYCLE ORDERING FIX — `prepared>0 => turn_id` INVARIANT RESTORED (2026-09-07)

- **Starting tree:** `02a9066` (clean). Objective: prove why a NORMAL new Send reached `prepared>0` while `turn_id=NULL`, restore the accepted-send lifecycle invariant, and close the Fedora lifecycle/recovery gate. DeepSeek V4 Pro owned architecture/integration/acceptance; no Harness worker was launchable for Antigravity/Gemini (see harness note below).
- **Root cause (proven, not guessed):** `send_staged_message_persist` created the accepted-import operation, then `accept_staged_materials` copied Materials and advanced the durable `copied` counter (`prepared`) to `N`, **before** `append_user_message` persisted the user turn and linked `turn_id`. The first durable `prepared>0` write (state `copying`, `copied=N`) therefore existed with `turn_id=NULL`. A kill (or any error in `resolve_agent_inputs_without_knowledge`) between those two points left exactly the operator's ledger: `state=copying prepared=52 indexed=0 ready=0 turn_id=NULL agent_state=not_started`. `RecoveryNoTurn` then correctly refused it (a prompt that was never durable cannot be reused). The bug is the ordering, not the safety boundary.
- **Fix (bounded, single-function reorder, no ledger redesign):** the user turn is now persisted before the operation ledger exposes `prepared>0`. `accept_staged_materials` no longer advances `copied`; `send_staged_message_persist` now binds Materials and writes the first `copied=N` state **together with** `turn_id` in one `update_accepted_import_operation`. Invariant restored: `prepared > 0 => turn_id != NULL`. A crash after copy but before turn now leaves `copied==0` (safe pre-turn denial), never a recoverable-looking `prepared>0` row without a turn.
- **Safety preserved:** `RecoveryNoTurn` unchanged (still terminal, still typed, still never fabricates a prompt); `StartedOutcomeUnknown` still never auto-resents; the legacy `turn_id=NULL, prepared>0` row is still denied; no duplicate turn/Material/membership/chunk; idempotent restart verified.
- **Tests:** new `accepted_staged_send_links_turn_before_prepared_counter_becomes_durable` pins the invariant (copied==3 ⇒ linked turn matching the single user message, no duplicates) against the real `AppState::send_staged_message_persist` path. Existing 52-file/51-file/repeated-restart/no-turn-denial/outcome-unknown tests unchanged and green.
