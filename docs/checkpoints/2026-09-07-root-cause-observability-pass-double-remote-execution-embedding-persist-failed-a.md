## ROOT-CAUSE + OBSERVABILITY PASS: DOUBLE REMOTE EXECUTION, `embedding_persist_failed`, AND RAW-FORWARDING CONTRADICTION (2026-09-07)

- **Starting tree:** `2e13130` (clean). Bounded pass proving and fixing three newly reported issues from a one-file real-AppImage run ("resumime el archivo" + one Markdown): (1) one logical Send produced two remote usages / two similar assistant responses; (2) local semantic indexing reported `embedding_persist_failed`; (3) Knowledge reported zero selected evidence / zero context tokens while the provider still summarized the attached file. No Windows work, no M11, no unrelated UX, not pushed, no AppImage (real-runtime §12 gate not yet executed this pass).
- **(A) Two remote executions — root cause proven in code:** the accepted staged send always ran `send_message_run` (normal chat). The frontend reopen-recovery seam (`App.tsx` effect) fires `agent_resume_import` for any incomplete operation with `agent_state == not_started` and `state != pending_retry/completed`. During a **live** first turn, before `run_accepted_staged_turn_inner` claims `StartedOutcomeUnknown` (which happens only after the local index + retrieval phase), a post-Send `onRefresh` re-delivered the same operation with `state = indexing_* / agent_state = not_started`, so the seam issued a **second** run on the same session (the two cumulative-session usages ~11500/60736 then a second ~3416/26880 delta) and produced a second, near-duplicate assistant message. Two concrete fixes: (1) the recovery seam now refuses to fire while that project's turn is in flight (`inFlightRef` / `agentPhase === "working"`); (2) summary intent is now routed in the accepted-staged path (below), so `send_summary_run` (K6) rather than a second `send_message_run` fulfills the request. Backend `agent_state` gates (unchanged) already refuse `started_outcome_unknown`.
- **(C) Raw file reached the provider despite zero Knowledge evidence:** the dedup predicate `indexed_source_names` was populated only from *retrieved* evidence entries. For a query that retrieves zero evidence (`resumime el archivo` has no lexical overlap with the corpus), `prepare_knowledge_context` returned `None`, so the indexed `notas`/Markdown attachment was raw-forwarded into `workspace/materials` exactly as any unsupported attachment (ADR-0011). Fix: `indexed_source_names` now keys off **every** durably READY-indexed source (`KnowledgeStore::ready_source_names()`), so supported indexed TXT/Markdown is never raw-forwarded even with zero retrieval; unsupported/media remain on their raw-forwarding path. `detect_summarize_intent` now also recognizes explicit single-source summary verbs (`el archivo`, `este documento`, `el material`, …), and the accepted-staged pipeline routes them to K6 single-document synthesis (bounded evidence), so a one-file "resumime el archivo" is summarized through labelled evidence instead of being raw-forwarded AND re-summarized by a normal chat run.
- **(B) `embedding_persist_failed` — root cause + fix:** the failure class was a lossy collapse — any `rusqlite`/`io` error at the `chunk_embeddings` insert/commit became `EmbeddingPersistFailed`, hiding the real cause (a transient `SQLITE_BUSY` from the recovery seam racing the WAL writer, since the connection had no `busy_timeout`). Fix: (1) `KnowledgeStore::open` now sets `busy_timeout=5000ms` so a brief lock wait does not abort the whole local index; (2) a first-class typed `KnowledgeError::EmbeddingPersistFailed` distinguishes persistence-only failures from inference/serialization failures, mapped to the pre-existing `SemanticProviderState::EmbeddingPersistFailed` and `MaterialIndexFailure::StorageFailed` (no DB/path leakage).
- **(§6/§7 telemetry + modal):** `SessionUsage` now carries `remote_calls`, `reason` (`normal_chat`/`summary_global`/…), and `additional_attachment_route`; K6 summarization turns now record an aggregated `SessionUsage` (all document/batch/global calls summed by `SummaryAccounting`), and missing fields render "No disponible" (never zero). The Conversation Details modal keeps "Uso real del proveedor" and "Optimización Knowledge (estimaciones locales)" separate, shows the remote-call count, and surfaces "El proveedor recibió contenido por una ruta adicional de adjuntos." when raw attachment content additionally crossed the boundary.
