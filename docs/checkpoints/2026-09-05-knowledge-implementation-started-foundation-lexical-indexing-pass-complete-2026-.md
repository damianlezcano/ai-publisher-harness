## KNOWLEDGE IMPLEMENTATION STARTED — FOUNDATION / LEXICAL INDEXING PASS COMPLETE (2026-09-05)

- **Scope completed:** the new backend-only `project-knowledge` crate implements the bounded local foundation for authorized immutable TXT/Markdown Material bytes: deterministic UTF-8 validation, LF + NFC normalization, structural chunks with provenance, SHA-256 identity/version metadata, a project-owned SQLite database at `projects/<project-id>/knowledge/knowledge.sqlite`, WAL, foreign keys, transactional schema v1, and SQLite FTS5 lexical search. It has no Tauri, OpenCode, provider, HTTP, model, embedding, vector, or packaging dependency.
- **Incrementality:** add indexes only the affected canonical document; unchanged same-byte/versioned material returns a no-op/reuse outcome before extraction/chunking; modified bytes replace only that document's derived rows transactionally; removal unlinks a Material and deletes only an orphan canonical document; same bytes under a renamed/new Material reuse the canonical document while retaining separate source provenance. Input bytes are supplied by the existing attachment/material boundary and are never rewritten.
- **Safety/privacy:** source paths are validated as fixed `inputs/<material-id>/<name>` metadata paths, while indexing accepts bytes rather than arbitrary host paths. Invalid UTF-8 and unsupported formats fail locally. The path is local extraction → hashing → normalization → chunking → SQLite/FTS only; document/chunk text is not logged and no OpenCode/provider call exists in this crate.
- **Explicitly deferred:** embeddings runtime and multilingual-e5-small download/tokenizer enforcement, vector storage/search, RRF hybrid fusion, Context Assembly/AgentEngine injection, summaries, PDF/DOCX/XLSX/PPTX/OCR/HTML extractors, and Knowledge UI/attachment-trigger wiring. Current structural sizing uses a conservative 1,600-character local bound; it is **not** E5-token validated. The approved future E5 input contract remains `query: <user query>` / `passage: <document chunk>`.
