## KNOWLEDGE K6 HIERARCHICAL MULTI-DOCUMENT SUMMARIZATION — COMPLETE (2026-09-05)

- **K6 COMPLETE:** the reusable hierarchical summarization layer now sits on top of K1–K5 with durable summary storage, deterministic hierarchy/reduction, incremental invalidation, cache reuse, bounded provider-independent remote synthesis, and structured-output validation. Ownership stays in the Knowledge/application layer: `project-knowledge` owns the plan/node model/fingerprints/invalidation/cache/state, and the provider-independent `RemoteSummarizer` trait is the only remote boundary. No NotebookLM end-user UI was built (deliberately out of scope).
- **Schema v4 (migration):** `knowledge.sqlite` gains `summaries(summary_id, level, state, failure_category, content_json, parent_summary_id, input_fingerprint, output_fingerprint, contract_version, generation_id, model_id, provider_id, created_at, updated_at)` plus `summary_sources`/`summary_chunks` association tables and `summaries_parent`/`summaries_state` indexes. Migration is deterministic and non-destructive: v1→v2→v3→v4 preserves documents/chunks/FTS/embeddings/material-index-state. `project-knowledge` tests: **34 PASS** (incl. `v3_migration_preserves_k1_k3_and_adds_summary_tables`, `summary_store_roundtrips_provenance_and_invalidates_transitively`).
- **Summary node model:** `SummaryLevel::{Document,Batch,Global}`, `SummaryState::{Pending,Ready,Failed,Stale}` (stale ≠ failed), sanitized `SummaryFailure::{ProviderUnavailable,ExecutionFailed,InvalidOutput,EmptyCorpus}`, structured `SummaryContent{summary,topics[],decisions[],action_items[],questions[]}` where each `SummaryItem{text,evidence[]}` carries `E1..`/`P1..` labels. Provenance: source document ids, chunk ids, parent lineage via `summary_sources`, generation/model/provider if used, input+output fingerprints, contract version `SUMMARY_CONTRACT_VERSION="v1"`, timestamps.
- **Hierarchy strategy (deterministic tree reduction):** L0 source chunks → L1 per-document → L2 batches → L3 global. `plan_project_summaries` reduces an ordered `(document_id, chunk_count)` list with `BatchOptions{branching_factor}` (default 10), so 100+ documents never trigger one unbounded request. A single-document project's document summary is its root. `plan_project_summaries` + `fingerprint_summary_inputs` + grouping are covered by unit tests (determinism, cache hit, changed-document lineage).
- **Document summary flow:** `KnowledgeStore::document_chunks` → `select_document_evidence` (≤32 labelled chunks) → `build_document_summary_request` (Spanish instruction enforcing "solo evidencia / sin fechas/entidades inventadas") → `RemoteSummarizer::summarize` → `validate_summary_output` (unknown evidence stripped, empty summary rejected) → `store_summary(Ready)`. Markdown headings remain provenance via chunks.
- **Multi-document synthesis flow:** `summarize_project` opens the store, lists `summary_document_levels`, plans, runs leaf-first; batch/global nodes consume only their child summaries (`build_synthesis_request`, `P1..Pn` labels), never the corpus. `synthesize_node` records per-request budget and call count in `SummaryAccounting`. Failed a child → downstream node `Failed(EmptyCorpus)`, never a fake global.
- **Cache/fingerprint:** reuse requires `Ready` AND current `input_fingerprint` (source ids + chunk ids + contract version + model id). `summary_state_survives_restart` and `single_txt_document_summarizes_and_reuses_cache` prove zero remote calls on a full cache hit and reuse across reopen.
- **Incremental invalidation:** `index()` invalidates only the changed document's lineage (`invalidate_document_summaries`), and `remove()` marks deleted-source lineage `Stale` transitively through `summary_sources`, leaving unrelated summaries `Ready` (`changed_document_invalidates_only_dependent_lineage`, `deleted_source_invalidates_dependent_lineage_not_others`).
- **Provider-independent execution:** `RemoteSummarizer` (Knowledge trait) is the boundary; `OpenCodeRemoteSummarizer` (app layer) drives the shared OpenCode backend in a **dedicated scratch session**, so background synthesis never creates a chat turn (`summarization_does_not_pollute_chat_history`) and never reuses history. No OpenAI/Anthropic/DeepSeek/Google/OpenCode message-format coupling at the orchestration boundary.
- **Offline/failure behavior:** failed synthesis marks `Failed` without replacing a `Ready` summary; a later successful run recovers (`retry_after_failed_synthesis_recovers`); provider-unavailable keeps cached ready summaries readable (`provider_unavailable_keeps_existing_ready_summary_readable`).
- **Privacy/budget:** the remote request carries only the bounded labelled evidence; no SQLite DB, vectors, model files, or absolute paths are sent (the request builder assembles `[label] (source): text` blocks only). Cost accounting (`SummaryAccounting`) tracks remote_calls, estimated input units, cache_hits, reused, regenerated, source_count, hierarchy_depth; no dollar pricing. No prompt/chunk/provider-secret/raw-request-body is persisted.
